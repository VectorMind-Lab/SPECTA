5. ARCHITECTURE DECISIONS
-------------------------
Agreed by the product owner (2026-09-15):
- Project folder:            SPECTA
- Android applicationId:     net.specta.app
- One APK for phone + TV
- State management:          Riverpod, pinned (flutter_riverpod 3.4.3; riverpod
                             3.4.3 declared for `Override` in tests)
- SQLite access:             Drift (drift 2.35.0 / drift_flutter 0.3.1 /
                             sqlite3 3.6.0, native-assets model)
- Playback:                  MediaKit (2E: wired behind the PlaybackEngine
                             seam — media_kit 1.2.6 / media_kit_video 2.0.1 /
                             media_kit_libs_video 1.0.7; MP4 + HLS only)
- JS runtime:                flutter_js 0.8.7 (QuickJS on Android)
- Cryptography:              cryptography 2.9.0 + cryptography_flutter 2.3.4

Phase 1 architecture (implemented and now device-verified):
- Extension execution: JS sandbox via flutter_js, with only two host channels
  registered (specta_request, specta_log) and no fetch/XHR enabled.
- Capabilities are declared in the manifest, are part of the signed payload,
  and are enforced by the runtime on every operation and channel call.
- Requests pass through an explicit transport policy (https/http, GET/POST/
  HEAD, size caps, redirect cap, clamped timeout) over dart:io.
- Ed25519 signature verification classifies TrustLevel. The private signing
  key is NEVER in the repository.
- Failure isolation: every extension error becomes a controlled
  ExtensionFailure; failed loads dispose their engine.
- IMPORTANT - do not overstate: this is a restricted API surface, not an
  OS-level sandbox. Extension JS runs in-process with no CPU/memory ceiling.
  See section 7 of docs/PHASE_1_REPORT.txt and section 7 of the closure
  report for exactly what is and is not enforced.

Schema discipline: every future version bump needs a registered migration step;
unregistered or backwards versions throw (SpectaMigrations.apply).


6. KNOWN LIMITATIONS
--------------------
- Player: device-verified on ONE device (SM-A065F, Android 16). No
  MediaKitPlaybackEngine unit test is possible without native code, so the
  engine seam is covered by the device suite instead (stated plainly, not
  faked). Embedded in-container audio/subtitle track selection is not
  surfaced yet (external subtitle tracks are); EngineTracksChanged/
  EngineSubtitleChanged are deliberate no-ops in the session.
- Player: a candidate that stalls rather than errors is detected only by the
  open/stall timeouts (45 s / 30 s, provider-overridable). Device tests use
  public third-party test streams; a host that stalls is honestly failed and
  the session advances (measured 2026-09-19).
- Player: watch progress is now PERSISTED (2F). The player reports through the
  same seam; a persistent LibraryStore row is written per playback identity.
  Quality selection remains 2D's ranking decision; the player never
  second-guesses it, and 4K smoothness is not promised on every device.
- Library (2F + resume follow-up): items display progress AND resume through
  the existing pipeline. Watchlist/favorites are not implemented (no affordance
  populates them). History is a per-identity view over `watch_progress`, not an
  append-only event log.
- Resume (2F follow-up): requires stored provenance. Items persisted before the
  follow-up have none and fail resume HONESTLY until played again. Resume
  re-fetches metadata and sources every time (never stale sources). The
  evidence-based metadata identity can collide for identical normalized
  (title, type, year) — pre-existing, unchanged by resume; a stricter provider
  identity is a separate architectural task.
- No CPU/memory ceiling for extension JavaScript (measured limitation).
- Not an OS-level sandbox; in-process restricted-API boundary.
- Redirect targets are now re-checked per hop (2G-C pre-flight); host
  blocking is best-effort and does not fully defeat DNS rebinding.
- Non-UTF-8 responses are returned as a lossy Latin-1 projection.
- Unverified extensions install and enable (trust is data, not enforcement);
  load-time trust re-classification from the file is enforced (2G-C
  pre-flight), but import-time copy + hash verification awaits 2H.
- Form factor TV detection is a viewport approximation.
- Release builds sign with the debug key and do not minify/shrink; Android
  backup is not configured though the DB holds watch history; cleartext HTTP
  release behavior is unverified. Distribution via app stores is likely
  restricted for an extension-based player. All recorded 2026-09-21
  (2G-C pre-flight, Tier 3).
- Home content is design fixtures until metadata/catalogue surfaces land;
  Search is live discovery from installed extensions only (no TMDB yet, by
  design until 2C). Details are live from installed extensions (2C); no
  TMDB/external metadata provider by design (not authorized).
- Pagination: contract page seam honored, load-more UI deferred (2C+).
- In-memory search cache: none (kept separate from durable data; add only on
  demonstrated need). Metadata is likewise in-memory only until 2F.
  Source pools are in-memory only; no source persistence before 2E/2G
  demonstrate a need.
- Details UI remains metadata-led; 2E added a Play action (movies) and
  per-episode play targets (series) instead of a source-selection UI — the
  source pool is resolved from provenance, never chosen by hand from a list.
- Device verification for 2B/2C/2D: not performed (no device attached; pure
  Dart pipeline + widget UI verified by unit/widget tests only). 2E IS device
  verified (5/5, SM-A065F) — see section 3.
- Source validation is structural only; no network reachability probes
  (deliberate: probes belong to playback's failure path through 2D's
  fallback seam).
- The Phase 0 home screen is preserved as Settings > Diagnostics, not the
  product home.
- cryptography_flutter and flutter_js apply KGP; a future Flutter release will
  refuse to build them. Upstream issue, documented, not suppressed.
- Android cmdline-tools absent; `flutter doctor` warns. Not build-blocking.
- Keep the Flutter SDK, pub cache and Gradle home off C:.
- build_runner 2.16.1 ignores --delete-conflicting-outputs.
- kotlin.incremental is disabled on purpose: the project path contains a space
  ("SPECTA APK"), which has corrupted Kotlin incremental caches.
