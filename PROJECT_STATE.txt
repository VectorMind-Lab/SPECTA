5. ARCHITECTURE DECISIONS
-------------------------
Agreed by the product owner (2026-09-15):
- Project folder:            SPECTA
- Android applicationId:     net.specta.app
- One APK for phone + TV
- State management:          Riverpod, pinned (flutter_riverpod 3.4.3; riverpod
                             3.4.3 declared for `Override` in tests)
- SQLite access:             Drift (drift 2.35.0 / drift_flutter 0.3.1 /
                             sqlite3 3.6.0, native-assets model)
- Playback:                  MediaKit (dependency baseline only, wired to
                             nothing)
- JS runtime:                flutter_js 0.8.7 (QuickJS on Android)
- Cryptography:              cryptography 2.9.0 + cryptography_flutter 2.3.4

Phase 1 architecture (implemented and now device-verified):
- Extension execution: JS sandbox via flutter_js, with only two host channels
  registered (specta_request, specta_log) and no fetch/XHR enabled.
- Capabilities are declared in the manifest, are part of the signed payload,
  and are enforced by the runtime on every operation and channel call.
- Requests pass through an explicit transport policy (https/http, GET/POST/
  HEAD, size caps, redirect cap, clamped timeout) over dart:io.
- Ed25519 signature verification classifies TrustLevel. The private signing
  key is NEVER in the repository.
- Failure isolation: every extension error becomes a controlled
  ExtensionFailure; failed loads dispose their engine.
- IMPORTANT - do not overstate: this is a restricted API surface, not an
  OS-level sandbox. Extension JS runs in-process with no CPU/memory ceiling.
  See section 7 of docs/PHASE_1_REPORT.txt and section 7 of the closure
  report for exactly what is and is not enforced.

Schema discipline: every future version bump needs a registered migration step;
unregistered or backwards versions throw (SpectaMigrations.apply).


6. KNOWN LIMITATIONS
--------------------
- No CPU/memory ceiling for extension JavaScript (measured limitation).
- Not an OS-level sandbox; in-process restricted-API boundary.
- Redirect targets are not re-checked against the scheme allow-list.
- Non-UTF-8 responses are returned as a lossy Latin-1 projection.
- Unverified extensions install and enable (trust is data, not enforcement).
- Form factor TV detection is a viewport approximation.
- The Phase 0 home screen is a temporary foundation screen, not the product UI.
- cryptography_flutter and flutter_js apply KGP; a future Flutter release will
  refuse to build them. Upstream issue, documented, not suppressed.
- Android cmdline-tools absent; `flutter doctor` warns. Not build-blocking.
- Keep the Flutter SDK, pub cache and Gradle home off C:.
- build_runner 2.16.1 ignores --delete-conflicting-outputs.
- kotlin.incremental is disabled on purpose: the project path contains a space
  ("SPECTA APK"), which has corrupted Kotlin incremental caches.
- This device suppresses app-level Dart debugPrint from logcat; the device
  verification marker trail lives in the test runner output (section 3).
